## 先说一下这辆车

为什么做这辆车呢，主要是兴趣再加上想试着学点东西

做这辆车之前，我以为最麻烦的事情会是调 PID。真正开始以后才发现，PID 反而不能一上来就动。接线、传感器、电机极性方向和编码器只要有一个地方不对，调出来的参数就没有意义。

我用的主控是 `NUCLEO-L432KC`（主要是学校微电子这门课强制用这个板子，我想试试在有限的资源下做项目就用了），姿态传感器是 `MPU6050`，蓝牙是 `HC-08`，电机则是带霍尔编码器的 `MG513` 减速电机。

最后用到三个控制环：

```text
角度环：让车站住
速度环：控制前进和后退
转向环：控制左右轮的速度差
```

虽然只有三个环，但这三个环是一个又一个套上去的。我是先把角度环单独调通，再加入速度环，最后才接转向环。

## 第一个坑不是算法，是接线

一开始 `MPU6050` 已经能正常通信，设备地址和 `WHO_AM_I`（我自己设置的调试节点） 都是 `0x68`。姿态数据也会变化，但电机控制一直不正常。

最大的问题是PWM、编码器和蓝牙之间的引脚设置出现了冲突。有些引脚在 `NUCLEO-L432KC` 上不方便接出来。

我重新分配了接口，最后使用的是：

```text
左电机 PWM：PA1 / TIM15_CH1N
左电机方向：PB1 / PB0
右电机 PWM：PA3 / TIM15_CH2
右电机方向：PA12 / PA4

左编码器：TIM1 -> PA8 / PA9
右编码器：TIM2 -> PA5 / PB3
```

接口确定后，我把实物接线、CubeMX 的 `.ioc` 文件和代码里的引脚定义一起改了，后面又把 `TIM15` 的 PWM 频率调到 `20 kHz`。

这里最容易出现的情况是：线已经换了，代码注释还是旧的；或者代码改了，`.ioc` 没有同步。表面上看是电机方向或者 PWM 有问题，其实三个地方写的根本不是同一套接线。

后来我每改一次引脚，都会同时检查接线、`.ioc` 和代码。先把这一层对齐，后面才开始看控制算法。

## 把角度算准

项目早期用过 DMP，数据可以正常出来。后来为了简便（主要是芯片资源还是够用），我换成了原始数据(Acc和Gy)加互补滤波。

加速度计根据重力方向计算俯仰角：

```c
AngleAcc = -atan2f(AX, AZ) * 180.0f / PI;
```

陀螺仪 Y 轴负责提供快速变化：

```c
AngleGyro = Angle + GyroRate * dt;
```

最后把两者合起来：

```c
Angle = Alpha * AngleAcc + (1.0f - Alpha) * AngleGyro;
```

我现在使用的 `Alpha` 是 `0.01`。简单来说，就是短时间内主要看陀螺仪，再用少量加速度计数据把长期误差拉回来。

### 车没动，角度却在变

刚开始看角度波形时，我发现车放着不动，`Angle` 还是会慢慢跑。于是我把 `AngleAcc`、`Angle` 和 `GY` 分开打印，最后看到静止时 `GY` 一直带着固定偏差。

陀螺仪数据需要积分，只要静止时不是 0，这个小误差就会一直累积。后面我根据静止波形修正 `GYRO_Y_OFFSET`，让 `GY` 基本回到 `0/1` 附近，角度才不再明显往一边漂。

这一步没做好之前，我调过的 PID 参数都不太可信。控制器看到的角度本身就在动，它当然会一直给电机错误的补偿。

### 直立不一定是零度

另一个问题是机械平衡点。我的车扶正以后，算法读到的角度并不是刚好 `0°`。传感器安装、车体重量分布和结构误差都会让真正的平衡位置带一点偏角。

所以我没有继续强行把目标设为 0，而是加了 `MECHANICAL_BALANCE`，用实测出来的角度作为平衡中心。


## 电机方向对了，车还是立不住

调到中间时，两个电机已经能同向转动。车往前倾，轮子会往前追；往后倾，轮子也会往后追。方向和极性都没问题，但车还是站不住。

到了这一步，看起来很像只剩 PID 没调好。后来才发现，我还忽略了 `MG513` 本身的机械特性。

### 小角度不动，大角度突然冲

`MG513` 的减速箱比较重，静摩擦也明显。

我当时看到的现象是：角度偏得不多时，PID 明明已经有输出，轮子却不动；等倾角继续增大，输出跨过起转门槛，电机又会突然往前冲。

这不是单纯把 `Kp` 调大就能解决的。`Kp` 太大只会让冲出去的那一下更猛。我后来在电机输出里加入了 `MOTOR_DEAD_ZONE`（电机死区补偿），给非零输出补上一段克服静摩擦的基础 PWM。

### 输出有 0.3，转成 PWM 却是 0

加完电机死区后，小角度下仍然偶尔没有反应。我继续往前查，发现 PID 的浮点输出在转换成整数时也会出问题。

比如 PID 输出是 `0.3`，直接转成整数后就是 `0`。控制量还没送到电机，就已经在代码里消失了。

我后来加了 `ControlToPwm()`，并设置：

```c
#define CONTROL_MIN_PWM 2
```

只要控制输出不是 0，转换以后就至少保留 `±2`。`MOTOR_DEAD_ZONE` 负责解决电机起转，`CONTROL_MIN_PWM` 负责避免小数被截断。

## PID 一个环一个环地加

角度环还没调稳时，如果速度环和转向环一起开着，车一动就很难判断到底是谁在影响输出。所以我先把两个外环关掉，只留角度环。

角度环的代码关系很直接：

```c
AnglePID.Actual = Angle;
PID_Update(&AnglePID);
AvePWM = ControlToPwm(-AnglePID.Out);
```

这一阶段我只检查几件事：车前倾时轮子追的方向对不对，角度在静止时会不会漂，小角度输出能不能真正让电机转起来。

这些都确认后，我才开始调参数。等小车可以靠角度环站住，再把速度环接回来。

速度环不直接给电机 PWM，而是修改角度环的目标：

```c
SpeedPID.Actual = AveSpeed;
PID_Update(&SpeedPID);
AnglePID.Target = MECHANICAL_BALANCE + SpeedPID.Out;
```

加上速度环后，我遇到过一种挺迷惑的现象：车没有马上倒，而是比较稳定地往一个方向走。继续改角度环没什么用。

速度环的积分一直在修改 `AnglePID.Target`，角度环只是照着这个新目标工作。后来我减弱速度环、限制它的输出，才没有继续压着角度环跑。

这时我才把“角度环是快环，速度环是慢环”理解成实际现象。同时，外环反应不能比内环还快，能修改目标的范围也不能太大。

最后加入的是转向环。它根据左右轮速度差算出 `DifPWM`，再和角度环的平均输出混合：

```c
LeftPWM  = AvePWM + DifPWM / 2;
RightPWM = AvePWM - DifPWM / 2;
```

编码器参数也按 `MG513` 重新算过。电机轴霍尔编码器是 `13` 线，四倍频，再乘 `30:1` 的减速比：

```text
13 × 4 × 30 = 1560
```

也就是说，输出轴转一圈对应 1560 个计数。

## 我后来是怎么看问题的

前期有不少时间花在“看起来像 PID”的问题上。后面蓝牙通信和波形输出整理好以后，调试才快了很多。

手机 APP 下发的控制指令从 `USART1_RX` 接收，调试波形和 `printf` 从 `USART2_TX` 发出去。收控制和看数据分开以后，不容易互相干扰。

我一般按下面的顺序看：

1. 先看 `GY`，确认陀螺仪静止时有没有明显偏差；
2. 再看 `AngleAcc` 和 `Angle`，确认方向、跟随速度和漂移；
3. 角度环稳定后，看 `SpeedPID.Target` 和 `AveSpeed`；
4. 最后看 `TurnPID.Target` 和 `DifSpeed`。

如果测量值不对，我就不调 PID；测量没问题以后，再检查电机方向；方向也对，才开始看增益大小（用蓝牙来调参看反应是真快）。这样做比拿着 `Kp`、`Ki`、`Kd` 来回试省时间。至少每次改参数之前，我知道自己想解决的是什么现象。

## PID 代码后来又改了什么

三个环都接上以后，我又改了几处 PID 代码。

第一处是积分限幅。角度环、速度环和转向环分别限制在 `±600`、`±150` 和 `±20`，避免误差存在太久以后，积分越积越大。

第二处是 `Ki` 设为 0 时清空积分。调试时我经常先关掉积分，只看比例和微分。如果积分还在后台累加，重新打开 `Ki` 时，电机会突然收到一大段旧误差。

第三处是把微分项改成对测量值做差：

```c
p->Out = p->Kp * p->Error0
       + p->Ki * p->ErrorInt
       - p->Kd * (p->Actual - p->Actual1);
```

蓝牙摇杆会快速改变目标值。这样改以后，目标突然变化时不会直接产生很大的微分冲击，在线调参也更好控制。

## 现在做到什么程度

目前小车已经可以直立，也能通过蓝牙控制前进、后退和转向。角度环、速度环和转向环都已经接上，参数和关键波形也能在线观察。

它还不是一辆调完以后就不用再动的车。电池电压、地面摩擦和负载发生变化，电机死区和控制效果都会跟着变。后面还可以继续记录不同状态下的参数，并补上更完整的失控保护。

如果现在让我重新从头调一次，我不会先去改 `Kp`。我会先核对接线和 `.ioc`，再看传感器静态数据，然后确认电机方向和死区，最后才轮到 PID。

这次花时间最多的地方，不是公式不会写，而是同一个“站不住”可能来自好几层问题。把这些问题一层一层拆开以后，车才慢慢变得能控制。
